# YooGram: что сделать в мобильной версии

Это список того, что уже сделано в десктопе и что нужно повторить в моде для телефона.
Всё ниже можно целиком скопировать и отдать как задачу.

Что НЕ нужно делать:
- Стеклянные меню (liquid glass): на мобильных они уже есть в самом Telegram.
- Журнал действий админа с фильтрами по типу действия и по админу: в Telegram он уже есть (Recent actions).
- Сам мут и бан: уже есть в окне прав участника. Нужны только быстрые кнопки (см. п. 2).

## 1. Значки профиля (кастомные бейджи)

Сервер уже готов (папка `.badge-server` в репозитории десктопа, Docker, веб-админка).
Клиент должен: скачать список, проверить подпись, показать значок рядом с именем.

### API

`GET {BASE_URL}/v1/badges`. Заголовок `If-None-Match: <ETag>`, если ответ уже был. При `304` ничего не менять.

Ответ:

```json
{ "payload": "<строка с JSON>", "sig": "<base64 подписи Ed25519>" }
```

Подпись считается от **точных байтов строки `payload` (UTF-8)**. Сначала проверить подпись, и только потом парсить `payload`.

Внутри `payload`:

```json
{
  "v": 1,
  "version": 12,
  "badges": {
    "123456789": { "kind": "emoji", "emoji": "✅", "color": "#2a9df4", "tooltip": "Developer" },
    "987654321": { "kind": "label", "label": "Developer", "color": "#ff0000" }
  }
}
```

- ключ в `badges` — Telegram user ID (число в виде строки);
- `kind = "emoji"`: рисуется эмодзи (как галочка верификации);
- `kind = "label"`: рисуется «таблетка» с текстом на фоне `color`;
- `tooltip` необязателен (подсказка по нажатию на значок).

### Правила клиента

1. Публичный ключ Ed25519 (32 байта, base64) **зашить в приложение**. Его показывает админка сервера внизу страницы и отдаёт `GET /v1/pubkey`.
2. Подпись неверна → список игнорировать, оставить прежний.
3. Если `version` меньше сохранённой → игнорировать (защита от подмены старым списком).
4. Хранить последний хороший список на диске; при недоступности сервера пользоваться им.
5. Обновлять при запуске и раз в 1–6 часов, с `ETag`.
6. Рисовать значок: профиль, заголовок чата (если это личный чат), список участников, подпись сообщения. Если у человека есть настоящий Telegram-значок (премиум, верификация), свой можно показывать рядом, а не вместо.
7. Не копировать вид галочки верификации Telegram один в один (чтобы не выдать за настоящую).

### Проверка подписи (Kotlin, BouncyCastle)

```kotlin
import org.bouncycastle.crypto.params.Ed25519PublicKeyParameters
import org.bouncycastle.crypto.signers.Ed25519Signer
import android.util.Base64

fun verify(payload: String, sigB64: String, pubKeyB64: String): Boolean {
    val key = Ed25519PublicKeyParameters(Base64.decode(pubKeyB64, Base64.DEFAULT), 0)
    val signer = Ed25519Signer()
    signer.init(false, key)
    val data = payload.toByteArray(Charsets.UTF_8)
    signer.update(data, 0, data.size)
    return signer.verifySignature(Base64.decode(sigB64, Base64.DEFAULT))
}
```

(Если мод на iOS: `CryptoKit` → `Curve25519.Signing.PublicKey(rawRepresentation:)` и `isValidSignature(_:for:)`.)

## 2. Быстрые действия модерации

Где: долгое нажатие на сообщение в **супергруппе**, если у вас есть право банить участников.
Новый пункт «Модерация» с подпунктами:

- Мут на 10 минут
- Мут на 1 час
- Мут на 1 день
- Бан (с подтверждением «Забанить {имя} из этой группы?»)

Когда НЕ показывать: свои сообщения, автор — админ или создатель группы, это пост канала или анонимный админ, служебное сообщение, обычная (не супер) группа.

### Запросы (MTProto `channels.editBanned`)

`channels.editBanned(channel, participant, banned_rights)`

**Мут** (`until_date = now + 600 / 3600 / 86400`), в `chatBannedRights` выставить `true`:
`send_plain, send_stickers, send_gifs, send_games, send_inline, send_polls, send_photos, send_videos, send_roundvideos, send_audios, send_voices, send_docs, embed_links`
(плюс `send_messages` / `send_media`, если в вашем слое они есть).

**Бан**: `view_messages = true`, `until_date = 0` (навсегда).

После успеха показать тост: «{имя} замьючен(а)» / «{имя} забанен(а)». При ошибке показать тип ошибки из ответа сервера (например, `USER_ADMIN_INVALID`).

В десктопе это реализовано в `Telegram/SourceFiles/yoogram/yoogram_moderation.cpp` (можно подсмотреть логику).

## 3. Раздел «YooGram» в настройках

Отдельный пункт в настройках приложения. Пока там один переключатель:

- «Быстрые действия модерации» (по умолчанию **включено**).

Хранить как обычный булев флаг в настройках приложения. Если выключен, пункта «Модерация» в меню сообщения нет.
Названия строк (для перевода): `YooGram`, `Moderation`, `Quick moderation actions`,
`Mute for 10 minutes`, `Mute for 1 hour`, `Mute for 1 day`, `Ban`, `Ban {name} from this group?`, `{name} muted.`, `{name} banned.`

---

## 4. Что понадобится от вас

- Адрес сервера значков (`BASE_URL`). Лучше домен через Cloudflare.
- Публичный ключ Ed25519 (из админки сервера).
- Выдавать значки: веб-админка сервера (`/admin`), вход по паролю из `.env`.

## Готовый промпт для ИИ/разработчика (скопировать целиком)

> Добавь в мобильный мод Telegram (YooGram) три вещи.
> 1) Кастомные значки: скачивай `GET {BASE_URL}/v1/badges` (с ETag), ответ `{payload, sig}`, проверяй подпись Ed25519 по зашитому публичному ключу над UTF-8 байтами строки `payload`, потом парси JSON `{v, version, badges:{<userId>:{kind: emoji|label, emoji|label, color, tooltip?}}}`. Игнорируй список при неверной подписи или меньшем `version`. Кэшируй на диск, обновляй при запуске и раз в 1–6 часов. Рисуй значок рядом с именем (профиль, личный чат, участники, сообщения): эмодзи или цветную таблетку с текстом.
> 2) В долгом меню сообщения в супергруппе (если есть право банить, автор не админ/создатель/я) добавь подменю «Модерация»: мут на 10 мин / 1 час / 1 день (`channels.editBanned`, все send-флаги в true, `until_date = now + срок`) и бан (подтверждение, `view_messages = true`, `until_date = 0`). Показывай тост с результатом или с типом ошибки.
> 3) Добавь раздел «YooGram» в настройки с переключателем «Быстрые действия модерации» (по умолчанию включён), который скрывает/показывает пункт из п. 2.
